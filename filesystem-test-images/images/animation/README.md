# Animation samples

Generated by scripts/generate-animation-fixtures.py using original artwork.
Open motion-palette.fli, .flc, .gif, .webp, .apng, and .mng in the image viewer.
Expect a moving ball, changing rainbow colors and frame counter, with a brief
intentional black frame halfway through. FLC pauses longer at frame 51. Motion
samples loop continuously in the player.
stored-objects.mng shows the same animation through hidden PNG objects, grouped
FRAM and SHOW commands.

interactive-regions.mng has two colored pointer regions. Touch/drag or hover a
mouse over either region, then leave it; the normal/left/right state should
follow the encoded events. States… provides direct selection and can disable
touch input to enable gallery swipes. Its input mask is a four-bit indexed PNG.

recoverable-header.flc deliberately lacks size/count/dimensions/default timing.
Its complete compressed rows/frames permit conservative recovery; expect a
recovery notice and a warning about fallback timing. The file is not rewritten.

gif-transparency-disposal.gif adds transparent partial frames, uneven delays,
and all three GIF disposal methods (keep, background, previous). It is included
in the whole-image-corpus Android render sweep described in
[the image fixture guide](../README.md).

`ora-embedded-iff.ora` is an OpenRaster stack with an embedded IFF palette-cycling
layer at `data/rainbow-logo.iff` above a static PNG base. The render sweep requires
the ORA viewer path to expose the IFF cycle and verifies that its rendered colors
change over time. This exercises an animation embedded as an ORA layer, as well
as standalone IFF and ORA still-image rendering.

The generator also writes ORA layer-source cases for animated FLI, FLC, GIF,
WebP, APNG, and MNG, plus transparent GIF/APNG disposal cases. Each archive
contains the animation under `data/` and a static PNG poster. The render sweep
requires the outer ORA decode to expose active playback and changing pixels for
each embedded format, rather than accepting the poster alone. These standard
ORA layer sources check that Canvas decodes embedded media rather than animating
a generated PNG overlay.

transparency-disposal.png is also animated despite its ordinary PNG extension.
It exercises translucent composition and background/previous disposal. It
stores a two-play count, which the player's default continuous looping overrides.
reference-frame-15.png is a static reference.

Try play/pause, the timeline, pinch zoom, background/foreground, rotation and
swiping between files. GIF/WebP progress is read-only; custom animation
timelines allow seeking, including while paused.
Editing freezes a still frame. Listing icons should remain still thumbnails.

These are generated acceptance samples. Run
python3 scripts/verify-visual-media-runtime.py from an Android device to render
the full image corpus through Canvas. See the fixture guide for current known
unsupported samples and runner requirements.
